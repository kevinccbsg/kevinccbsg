# Hi, I'm Kevin 👋

Software Architect at [Orbitant](https://github.com/weorbitant), based in Madrid. I created **TWD (Test While Developing)**, an open source testing ecosystem I build with the team at [BRIKEV](https://github.com/BRIKEV).

I care about testing strategy, developer experience and adopting AI responsibly. The idea behind everything I work on: tests should run while you develop, not after, whether you write them or your AI agent does.

## TWD - Test While Developing

Frontend tests that run in the browser you develop in, against your real app. No jsdom, no separate E2E stack. Works with React, Vue, Angular, Solid, Astro, Nuxt and more.

| [twd-lint](https://github.com/BRIKEV/twd-lint) | [![npm](https://img.shields.io/npm/v/twd-lint)](https://www.npmjs.com/package/twd-lint) | Catches test mistakes (missing `await`, Vitest imports, leftover `it.only`) in the editor and in CI, and fixes the safe ones. [Docs](https://twd.dev/linting) |
| [twd-ai](https://github.com/BRIKEV/twd-ai) | | Claude Code plugin and Agent Skills: your agent writes, runs and fixes TWD tests. |
| [openapi-mock-validator](https://github.com/BRIKEV/openapi-mock-validator) | [![npm](https://img.shields.io/npm/v/openapi-mock-validator)](https://www.npmjs.com/package/openapi-mock-validator) | Checks every API mock against the real OpenAPI spec. |

Start at [twd.dev](https://twd.dev/). The thinking behind the approach lives in [twd-principles](https://github.com/BRIKEV/twd-principles).

### TWD Design

[design.twd.dev](https://design.twd.dev/): agree on the screen before anyone builds it. Describe a screen in Slack and get a clickable prototype in your design system, with acceptance tests that already pass, and a pull request when the team approves. Open source, self-hosted, stores nothing.
